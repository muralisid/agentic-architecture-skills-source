## Why putting everything in one place is only a beginning

A straightforward starting design is to collect manuals, inspection reports, work orders, and conversation history in one searchable store. The agent can now find relevant material. That is useful, especially for questions about relatively stable documents.

But relevance alone does not settle the pump investigation. A report can discuss the same symptom on another asset. A summary can omit that a repair was completed. An old procedure can use almost the same words as its replacement. More retrieved text can contain all of these possibilities without telling the agent which one applies.

The purpose of knowledge and memory design is to make those distinctions recoverable. Before choosing storage technology, ask what the next task will need to establish and what it must be able to check.

## Follow one investigation through the evidence

Our illustrative agent is investigating pump P-17. It needs to establish the asset identity, read the procedure that applies today, compare current behavior with past episodes, and check whether an earlier fault was repaired. Those are different questions, even though they belong to one task.

<TeachingIllustration src="/figures/memory/question-map.svg" mobileSrc="/figures/memory/question-map-mobile.svg" title="One pump, different questions" alt="Exact records establish identity; document versions establish procedure; time-series comparisons find similar behavior; relationships trace dependencies; media preserves an observation." caption="Exact records establish identity; document versions establish procedure; time-series comparisons find similar behavior; relationships trace dependencies; media preserves an observation." />

This is why a single retrieval method is not automatically the answer to every memory problem. An exact lookup can identify P-17. Document search can find its procedure. A suitable time-series representation can help find similar behavior. Relationships can connect a bearing replacement to a work order. Each helps preserve a different part of what the agent needs to know.

**Start here:** [choose the representation for the question](/memory/choosing-representations). The point of a vector is to make a useful kind of resemblance searchable. The question determines which similarities matter and which differences must remain visible.

## Keep enough context to check a remembered fact

Suppose the agent stores “bearing replaced” after reading a work order. The short note looks useful, but a later task needs to know which bearing, on which pump, when, and whether completion was confirmed. Without those details, compression has removed the part that makes the memory usable.

Keep the original evidence and the information needed to find it again. A summary can help the agent navigate; the underlying record lets it verify the claim. [From information to usable memory](/memory/information-to-memory) explains what to preserve during preparation.

## Remember what changed, not just what was said

The inspection may correctly say that a bearing was faulty on 12 May. A completed repair may change the situation on 14 May. Deleting the inspection would lose useful history, but presenting it as the current condition would mislead the next investigation.

<TeachingIllustration src="/figures/memory/fact-timeline.svg" mobileSrc="/figures/memory/fact-timeline-mobile.svg" title="Facts change with events" alt="An inspection on 12 May finds a fault, a repair on 14 May changes the situation, and a question on 18 May needs current evidence while preserving the old inspection as history." caption="Keep historical evidence and current condition distinguishable." />

[Changing facts](/memory/changing-facts) explains how versions and events affect an answer. [Permissions and lifecycle](/memory/permissions-and-lifecycle) explains why a copied summary or index entry needs an update and access policy too.

## Extend the same reasoning beyond documents

A sentence describing a video is not the video. A regional satellite representation is not a current measurement of clearance from a power line. An average vibration level is not the pattern of a developing fault. The representation should retain what the intended question needs.

## Choose the design after the problem is clear

Now the storage and retrieval choices have a purpose: preserve the distinctions the investigation needs, find them efficiently, and keep them valid as sources change.

- [Six memory approaches](/memory/six-architectures): compare what each retains and what it may leave out.
- [Long context and retrieval](/memory/long-context-is-not-memory): decide when more material in the working context helps.
- [Large context at enterprise scale](/memory/the-ten-million-token-question): examine the evidence behind much larger workloads.
- [What benchmarks measure](/memory/what-the-benchmarks-measure): check whether a reported score tests your problem.
- [What we measured](/memory/what-we-have-measured) and [retrieval patterns](/patterns): read findings with their controls and limitations.

A practical test is to ask about the wrong asset, a repaired fault, an inaccessible record, and a question with no supporting evidence. A useful memory should help the agent recognize these differences, rather than merely find plausible text.
