An agent needs information it can use and evidence we can check. **How should the enterprise organize what it knows so that an agent can find the right material and show what supports its decision?**

The [architecture](/architecture) places memory within the enterprise system. The [Intelligence ladder](/ladder) explains how to build the capability the task needs at an acceptable cost. Here we explore the second pillar: representing enterprise information, finding it again, and retaining a traceable basis for decisions.

## First, get a feel for memory in vector space

An enterprise holds words, photographs, recordings, maps, and readings over time. Turning all of them into short text summaries is convenient, but can lose precisely what a later question needs: a visual feature, a sequence of events, a surface pattern, or a changing signal.

The illustrations are **conceptual maps, not measured embeddings**. Start with text, then look at what changes for other forms of information.

## Text: find related meaning

<TeachingIllustration src="/images/memory/text-space-v1.webp" title="Text: find related meaning" alt="Text encoder maps two differently worded pump-pressure passages near each other and a leave-policy passage elsewhere. A query retrieves nearby passages while retaining the original source, version, and permissions." caption="Text similarity helps locate a passage. It does not establish whether that passage is current or applicable." expandable />

An embedding represents selected features as numbers so a search can find useful similarities. Picture a space in which related examples lie near each other. What counts as related depends on the model and its training. Actual spaces have many dimensions; a two-dimensional illustration cannot show every relationship.

A representation is not the whole memory. Keep the original sources, exact records, dates, and access rules alongside it. Start with the kind of question the agent will ask.

“Pump pressure is falling” and “low discharge pressure” may belong near each other even though their words differ. This helps find relevant procedures or earlier incidents. An exact asset number, policy version, or quantity still needs an exact check.

## Images: find visual resemblance

<TeachingIllustration src="/images/memory/image-space-v1.webp" title="Images: find visual resemblance" alt="Two inspection photographs of corroded pipe joints map to nearby points while clean-valve images form a different group. An aligned text-image model can connect a phrase to visual results. Each result links back to the original image." caption="Inspect the original image, date, and asset. Visual resemblance is not a diagnosis." expandable />

A model can place visually related inspection images near each other, making it possible to look for earlier examples of corrosion or damage. With a suitably aligned text-image model, a written query can also find images. What counts as similar depends on training.

[Explore this memory type](/memory/image-embeddings).

## Video: find a similar event

<TeachingIllustration src="/images/memory/video-space-v1.webp" title="Video: find a similar event" alt="A timestamped CCTV clip becomes a representation of an event interval. Similar filmstrips are grouped together; a retrieved result opens the original clip with its camera, start and end time, and surrounding context." caption="Keep timestamps and original clips. A vector is not a directly readable event chronology." expandable />

A video contains change: a person approaches a loading zone, a vehicle moves, or an inspection unfolds. A suitable representation can help search for similar clips or events. Finding a related video is different from locating the exact interval that supports a claim.

[Explore this memory type](/memory/video-embeddings).

## Audio: find a similar sound

<TeachingIllustration src="/images/memory/audio-space-v1.webp" title="Audio: find a similar sound" alt="Pump recordings with rattling patterns are grouped separately from a steady hum. Each match opens a recording with equipment and interval metadata. A speech transcript is shown as a separate representation." caption="Listen to the original and check operating conditions. Similar sounds need not have the same cause." expandable />

A pump rattle and a spoken maintenance instruction need different kinds of information. Sound representations can help find acoustic resemblance; a transcript can help find words. Choose the form that preserves what the question asks about.

[Explore this memory type](/memory/audio-embeddings).

## Geospatial data: find similar places or change

<TeachingIllustration src="/images/memory/geospatial-space-v1.webp" title="Geospatial data: find similar places or change" alt="Earth patches containing forest, water, fields, and mining ground map into groups by learned surface characteristics rather than physical distance. Yearly representations can be compared, while coordinates, observation intervals, and source observations remain attached." caption="Nearby in the representation does not mean nearby on Earth. Annual patterns do not identify an exact event date." expandable />

A place can be represented by learned surface characteristics and, in some models, behavior over a period. Distant areas may be similar in that space. Comparing the same location across years can guide a change investigation, while exact coordinates and dates remain explicit.

[Explore this memory type](/memory/location-and-satellite-data).

## Time-series data: find similar behavior

<TeachingIllustration src="/images/memory/time-series-space-v1.webp" title="Time-series data: find similar behavior" alt="Operating windows with growing oscillations and a spike form a different group from steady signals. A query finds comparable historical windows and returns original readings and confirmed outcomes, with units, duration, and operating state." caption="A similar operating pattern suggests an investigation. It does not establish the same underlying cause." expandable />

The useful resemblance may be a developing oscillation, a spike, or a sequence of changes across pressure and vibration. This lets an agent ask, “What behaved like this before?” Decide whether shape, magnitude, duration, or operating state should matter.

[Explore this memory type](/memory/time-series).

## These are different spaces, not one universal memory map

Two models can produce vectors of the same length without giving those coordinates the same meaning. Search within a suitable space and combine the resulting evidence by asset, place, time, and source. A jointly trained or explicitly aligned model can support some cross-modal comparisons; do not assume every combination is aligned.

These six types describe the **form of information**. A different question is how long an agent should retain it and how it should be stored. Task context, past events, approved procedures, source records, summaries, and relationships can each use different representations. The [six memory designs](/memory/six-architectures) examine those storage choices.

## Then organize memory around evidence and decisions

Once the representations make sense, the organization problem becomes clearer. A familiar starting design is to put everything into an index and retrieve the closest results. That helps discover material. It does not by itself establish that a result concerns the right asset, remains current, is accessible to this user, or supports the proposed action.

<TeachingIllustration src="/images/memory/evidence-organization-v1.webp" title="Organize memory so a decision can be checked" alt="Original records and media feed separate representations. Retrieval checks asset identity, time, access, and version. An evidence folder keeps citations and unresolved contradictions. A decision record retains the evidence used, rationale, approval, and outcome. Corrections propagate to derived information." caption="A vector helps locate evidence. The decision must remain traceable to the original sources and the versions used." expandable />

**Preserve the source.** Keep the original passage, image, recording, or observation window and the information needed to locate it. A generated summary should not be the only surviving evidence. [Prepare usable memory](/memory/information-to-memory).

**Represent for the question.** Use exact queries for official identifiers and values, lexical search for precise terms, suitable embeddings for resemblance, and relationships where the question requires them. [Choose a representation](/memory/choosing-representations).

**Retrieve and check.** Check identity, observation period, version, and current permissions. Keep conflicts visible instead of silently blending them. [Combine evidence](/memory/combining-evidence), handle [changing facts](/memory/changing-facts), and maintain [access and lifecycle](/memory/permissions-and-lifecycle).

**Keep a decision record.** Retain the request, the source references and versions used, the evidence relevant to the decision, unresolved uncertainty, a concise rationale, required approval, and the observed outcome. A rationale should explain the decision against the evidence; storing private model reasoning is not required. A citation makes inspection possible, but does not by itself establish that the decision was correct.

## Test whether memory serves the work

Ask whether the agent found the right evidence and whether a reviewer can follow the answer back to it. Include wrong-asset matches, repaired faults, changed permissions, misleadingly similar images, and questions with no supporting evidence. Measure retrieval quality, decision quality, review effort, latency, and full operating cost.

Go deeper into [long context](/memory/long-context-is-not-memory), [enterprise-scale history](/memory/the-ten-million-token-question), [benchmark interpretation](/memory/what-the-benchmarks-measure), and [reported experiments](/memory/what-we-have-measured). Apply the design to [compliance evidence](/use-cases/compliance-evidence) or a [water-operations investigation](/use-cases/water-operations).
