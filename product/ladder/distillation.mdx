<Slide journey="ladder/distillation" id="di-01">

Every other step on this ladder tries to make an agent better. This one keeps the quality about the same. Instead, it makes the agent cheaper and faster. It works by having a large model teach a small one. This is called distillation.

</Slide>

<Slide journey="ladder/distillation" id="di-intro">

The ladder is the order in which to try changes to an agent. The early steps change the system around the model. The later steps change the model itself. Distillation is one of those later steps.

First, we look at how one model teaches another.

Then we see how the same idea repairs a model that forgot skills.

Next, we work out when distillation pays for itself.

Then we see how two models can share the work.

Last, we look at where to go next.

</Slide>

<Slide journey="ladder/distillation" id="di-02">

Distillation does two different jobs. The first job is cutting cost. It helps with work that runs a very large number of times.

The second job is a repair. A model can be trained further on your own examples. This is called fine-tuning. Fine-tuning can damage skills the model already had. Distillation can repair that damage.

</Slide>

## How a model teaches a model

<Slide journey="ladder/distillation" id="di-20">

So how does one model teach another? Start with a large model that already does the task well. Its answers are good. But it is slow and costs a lot to run. In distillation, this large model is called the teacher.

</Slide>

<Slide journey="ladder/distillation" id="di-21">

Next to it, we put a much smaller model. A small model is cheaper and faster to run. It learns to do the task by copying the teacher. This small model is called the student.

</Slide>

<Slide journey="ladder/distillation" id="di-22">

To see how the teaching works, look at how a model writes. It writes its answer one word at a time. At each step, some words look more likely than others. The word it picks at each step is called the next word.

</Slide>

<Slide journey="ladder/distillation" id="di-03">

Fine-tuning shows a model only the right next word. Say that word is transferred.

Distillation shows the student more than that. The teacher also shows that the word moved was nearly chosen.

And it shows that the word flew was never likely at all. These near misses tell the student a lot more than one right answer. So a student can get close to its teacher without much training.

</Slide>

<Slide journey="ladder/distillation" id="di-04">

There is a newer way to do this. In the newer way, the student tries the task first.

Then the teacher grades the student's own attempt.

The student learns from that grade. So it learns from the mistakes it really makes. This is called on-policy distillation.

</Slide>

<Slide journey="ladder/distillation" id="di-05">

Training a model takes a lot of computing power. Published work compared this newer way with simply doing more fine-tuning. It reached about the same quality. And it used 9 to 30 times less computing power to train.

</Slide>

## The second use: repairing forgetting

<Slide journey="ladder/distillation" id="di-06">

Now to the second job, the repair. Fine-tuning a model on your own examples makes it better at your work. But it also makes the model worse at general tasks. It has partly forgotten skills it used to have. Even fine-tuning that changes only a small part of the model does not prevent this.

</Slide>

<Slide journey="ladder/distillation" id="di-07">

The published repair uses a special teacher. The teacher is the same model before it was fine-tuned.

The fine-tuned model is the student. It learns its general skills back from the model it used to be. And it keeps the new skills it just gained.

</Slide>

<Slide journey="ladder/distillation" id="di-08">

So distillation is not only a way to save money. It is also maintenance you plan after training a model further. Plan it after fine-tuning. There is another way to train a model further. You train it on plain text from your own field. That is called continued pretraining. Plan the same repair after that too.

</Slide>

<Slide journey="ladder/distillation" id="di-23">

How do you know if a repair is needed? Keep a test of general skills. Run it after each round of training. If the scores drop, plan the repair. While the repair runs, keep testing the new skills too. That shows you whether the repair is undoing them.

</Slide>

## When it pays: the arithmetic

<Slide journey="ladder/distillation" id="di-09">

Now back to the first job, saving money. Distillation has a cost you pay once. That is the cost of building the student.

After that, every request to the student costs less. One request to a model is called a call. Divide the one-off cost by the saving on each call. That tells you how many calls it takes to pay the cost back.

Then compare that with the number of calls you really make. No general number tells you when it pays. You have to use your own costs and volumes.

</Slide>

<Slide journey="ladder/distillation" id="di-10">

Distillation also needs the right kind of task. A small student cannot match a large teacher at everything. It can match the teacher only on a narrow task. The narrower the task, the smaller the student can be.

</Slide>

<Slide journey="ladder/distillation" id="di-24">

You also need proof that the student is good enough. That proof comes from a test. Write the test before you build the student. Then do not change it. A test kept fixed like this is called a locked test.

</Slide>

<Slide journey="ladder/distillation" id="di-11">

A locked test can clash with another goal. Proving the saving needs a test that stays the same. But some teams keep improving their agent all the time. That work keeps rewriting the test. So decide which of the two you are running.

</Slide>

<Slide journey="ladder/distillation" id="di-12">

The student copies everything the teacher does. That includes the teacher's mistakes. The teacher's large size sometimes saved it from a mistake. The small student does not have that size. So there is one hard rule. Never distil a skill the teacher does not reliably have.

</Slide>

## Splitting work between two models

<Slide journey="ladder/distillation" id="di-15">

Distillation also lets two models share the work. Say most of the requests an agent gets are routine. The large model handles them well. But it costs too much to run on every one of them.

So the small student handles the routine requests. The unusual ones still go to the large model. The average cost per request drops a lot.

</Slide>

<Slide journey="ladder/distillation" id="di-25">

How does each request reach the right model? The student checks how sure it is of its answer. If it is not sure enough, the request goes up to the large model. This check is called a confidence rule.

</Slide>

<Slide journey="ladder/distillation" id="di-16">

Do not guess which requests are routine. Use your test. It shows which requests the student handles as well as the large model. Send only those to the student. How much this saves depends on your own volumes. So no general number is claimed for it.

</Slide>

## The test

<Slide journey="ladder/distillation" id="di-18">

The last question is where distillation fits. It comes after the other ways of improving an agent. It does not replace them. Now say the agent's judgement is still wrong. And its results are the kind you can check and score.

There is a way to train a model on scored attempts. It is called [reinforcement fine-tuning](/ladder/reinforcement-fine-tuning). That is where to go next.

</Slide>

## What to remember

<Slide journey="ladder/distillation" id="di-recap">

Here is what to remember. Only distil what the teacher already does well. The student copies its mistakes too.

A small student is cheaper and faster to run than its teacher.

The same method repairs what a model forgets after fine-tuning.

Whether it pays depends on your own costs and volumes.

And lock the test before you build the student. Next, we look at reinforcement fine-tuning.

</Slide>
