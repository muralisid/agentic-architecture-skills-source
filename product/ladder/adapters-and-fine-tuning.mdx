<Slide journey="ladder/adapters-and-fine-tuning" id="ad-intro">

This video covers adapters and fine-tuning. The first three steps of the ladder change the system around the model. The model itself stays the same. This is the first option that changes the model itself.

First, we look at what training on examples really does. Then we see three ways to do it and what you need before you start. Next, we see how to move work to a smaller model. Last comes the test for moving on.

</Slide>

## What training on examples actually does

<Slide journey="ladder/adapters-and-fine-tuning" id="ad-22">

Until now, the model itself stayed the same. Now you change it. You collect many examples of the task done well. Each example is an input paired with the answer you wanted.

The model is trained on these pairs until it answers more like them. Each example shows the model the right answer to aim for. Training a model this way is called supervised fine-tuning. From here on, we will just say fine-tuning.

</Slide>

<Slide journey="ladder/adapters-and-fine-tuning" id="ad-02">

Fine-tuning is the right tool for two jobs. It makes the model behave the same way every time. And it can move work to a smaller, cheaper model.

It is the wrong tool for teaching the model facts. The next slides show why.

</Slide>

<Slide journey="ladder/adapters-and-fine-tuning" id="ad-03">

To see why, look at what training does inside the model. A model is a huge set of numbers. These numbers are called weights. Training shows the model an input and the answer you wanted.

It measures how far the model's own answer is from that. Then it nudges the weights a little to close the gap.

This repeats over thousands of examples. Slowly, the model's usual behaviour moves toward the pattern the examples share.

</Slide>

<Slide journey="ladder/adapters-and-fine-tuning" id="ad-04">

Training rewards answers that look like your examples. So the model learns their structure, their tone and their confidence. Nothing in the process stores the facts behind them.

A few thousand examples cannot carry a million facts. So a fine-tuned model can sound just like your examples and still get details wrong.

</Slide>

<Slide journey="ladder/adapters-and-fine-tuning" id="ad-14">

So where should facts come from? Look them up at the moment the model needs them. Then pass them to the model with the question. This is called retrieval.

Facts baked into the weights cannot be traced back to a source. They cannot be updated or deleted either.

Facts that are looked up can be traced, updated and deleted.

</Slide>

<Slide journey="ladder/adapters-and-fine-tuning" id="ad-05">

Fine-tuning also has a side effect. The weights being nudged also hold the model's general skills. If you push them hard toward your task, they drift. The model can lose skills it had before. This is called catastrophic forgetting.

</Slide>

## Three ways to fine-tune

<Slide journey="ladder/adapters-and-fine-tuning" id="ad-06">

Now for how fine-tuning is actually done. There are three main ways. The first changes every weight in the model. This is called full fine-tuning.

It has the most power to change behaviour. It also needs the most computing power. And you end up with a whole new model to store and run.

</Slide>

<Slide journey="ladder/adapters-and-fine-tuning" id="ad-07">

The second way leaves the model's own weights locked. The change fine-tuning makes can usually be captured in two small tables of numbers. So only those two small tables are trained.

When the model runs, their effect is added on top. This method is called LoRA.

</Slide>

<Slide journey="ladder/adapters-and-fine-tuning" id="ad-23">

A whole model takes gigabytes of space. What LoRA produces takes only megabytes. This small add-on is called an adapter.

You can keep one shared model running. Then you swap in a different adapter for each task. So one model can do many different jobs.

</Slide>

<Slide journey="ladder/adapters-and-fine-tuning" id="ad-08">

The third way builds on LoRA. While the adapter trains, the locked model is stored in a compressed form. That saves so much computer memory that one powerful chip can adapt a large model.

The adapter itself is not compressed. The quality stays close to LoRA. This method is called QLoRA.

</Slide>

<Slide journey="ladder/adapters-and-fine-tuning" id="ad-09">

Changing fewer weights sounds safer. You might expect an adapter to protect the model's other skills. But published research found that LoRA does not protect them. If forgetting matters for your use, measure it.

</Slide>

## What you need before starting

<Slide journey="ladder/adapters-and-fine-tuning" id="ad-12">

Whichever way you choose, first check that fine-tuning fits your problem. Here is the typical case.

The answers are already correct.

But their structure and tone still vary from one answer to the next.

Adding example answers to the instructions has not fixed it.

</Slide>

<Slide journey="ladder/adapters-and-fine-tuning" id="ad-10">

You need a few thousand examples. The model learns exactly what they teach. That includes their mistakes. So their quality matters more than anything else.

Before training, write a set of tests and lock them. Include tests for skills that should not change. If you only test the new task, forgetting can slip through unnoticed.

You also need a plan to run the result. An adapter needs its original model to run on. When that model is replaced, the work must be redone and tested again.

</Slide>

## Services that fine-tune for you

<Slide journey="ladder/adapters-and-fine-tuning" id="ad-24">

The training itself has to happen somewhere. You do not have to use your own machines. Some providers run fine-tuning for you as a service. This is called a managed option. You send the examples and get back the trained result.

</Slide>

<Slide journey="ladder/adapters-and-fine-tuning" id="ad-11">

These managed options changed in 2026. This fact changes often. It is correct as of August 2026.

OpenAI is closing the fine-tuning that customers set up themselves. It is closing in stages. Remaining customers can start no new jobs after 6 January 2027.

Managed fine-tuning on the major cloud platforms is still available.

Some models let you download their weights and run them yourself. These are called open-weight models. Adapters on these models are unaffected.

</Slide>

## Moving work to a smaller model

<Slide journey="ladder/adapters-and-fine-tuning" id="ad-15">

Now back to one of the two jobs fine-tuning is good for. The biggest and most capable models cost the most to run. These are called frontier models.

Fine-tuning can move a task from a frontier model to a small one. A small fine-tuned model can do the task for a fraction of the cost. It can run on your own servers. Your data then stays with you.

</Slide>

<Slide journey="ladder/adapters-and-fine-tuning" id="ad-16">

One published test compared a small fine-tuned model with a frontier model. The frontier model was given careful instructions instead. The task was putting items into the right category. The small model won by a wide margin at far lower cost.

But that is only one test. Prove it on your own tests before you switch.

</Slide>

## The test for moving on

<Slide journey="ladder/adapters-and-fine-tuning" id="ad-18">

So when is this step done? Move on when the format and behaviour of the answers are right. At that point, what is still wrong is judgement or knowledge. Where you go next depends on which one it is.

</Slide>

<Slide journey="ladder/adapters-and-fine-tuning" id="ad-19">

Say the answers look right, but the reasoning is wrong. And say a program can check whether each outcome is right. Then go to [reinforcement fine-tuning](/ladder/reinforcement-fine-tuning). There, the model tries the task and learns from the scores it gets.

</Slide>

<Slide journey="ladder/adapters-and-fine-tuning" id="ad-20">

Say the model still misreads the language and documents of your field. Then go to [continued pretraining](/ladder/continued-pretraining). There, the model keeps learning from large amounts of your own text.

</Slide>

<Slide journey="ladder/adapters-and-fine-tuning" id="ad-21">

Say the quality is right, but it costs too much or runs too slowly. Then go to [distillation](/ladder/distillation). There, a large model trains a small one to do the same work.

</Slide>

## What to remember

<Slide journey="ladder/adapters-and-fine-tuning" id="ad-recap">

Fine-tuning trains a model on examples of a task done well. It makes behaviour consistent. It does not teach the model facts. Facts should still be looked up when the model needs them.

Training can make the model forget other skills. Adapters do not stop this. So measure it. An adapter is a small add-on you can swap for each task. Fine-tuning can also move work to a smaller, cheaper model.

Next up is distillation.

</Slide>
