An assistant recommends inspecting a bearing that was replaced yesterday. Calling it a “reasoning failure” suggests a stronger model. But perhaps the repair record was never supplied, the wrong asset was retrieved, or the tool returned an error that the agent ignored. These failures need different remedies.

## Run a comparison that separates the causes

First give the same model the correct asset record and confirmed repair, leaving the task unchanged. If the answer improves, investigate the information path. If it still fails, clarify the expected result and inspect the reasoning against the evidence. If it proposes the right action but cannot complete it, inspect tools, permissions, and confirmation. Only then compare models or training approaches against the remaining failure.

This is an illustrative diagnostic exercise. A single successful answer is not enough to establish the remedy. Repeat the comparison on representative cases, including ones where no repair occurred.

## Start with a failed task

Keep the request, allowed actions, evidence available at the time, tool results, and observed outcome. Ask the domain owner what a successful result would have looked like. A vague complaint such as “the agent is unreliable” is not enough to select a remedy.

## Check the information

Could the agent access the correct source? Was the information current and did it survive parsing? If the needed evidence never reached the model, additional training may hide rather than repair the failure. Try a controlled test with the correct evidence supplied.

## Check the task and tools

Was the instruction ambiguous? Could the tools perform the required operation? Did the agent distinguish a submitted request from a completed action? Inspect tool errors, permissions, and retry behavior before changing the model.

## Check the workflow

A known sequence may be better expressed as a workflow. An investigation with uncertain next steps may benefit from a bounded agent loop. Use several agents only when specialization or independent work improves the measured result.

## Then assess model adaptation

If the task, evidence, and tools are adequate, compare model choice, examples, fine-tuning, and other adaptation methods. Use held-out tasks and include maintenance cost. A new model that improves an automated score but creates more expert review is not an unqualified improvement.
