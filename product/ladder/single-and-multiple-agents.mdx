## A workflow when the sequence is known

A scheduled report or a validated document-processing sequence may not need an agent deciding every step. Keep predictable operations explicit. A workflow can call models for individual tasks without giving them control of the whole process.

## One agent for a bounded investigation

An agent can select a useful tool, inspect what it returns, and decide whether more evidence is needed. Give it a task owner, tool permissions, and time and cost limits. Define what counts as enough evidence and when to ask a person.

## Several agents when separation helps

A compliance investigation might involve distinct document, asset, and departmental capabilities. Separate agents can be useful when their responsibilities, tools, or work can be clearly separated. Measure coordination overhead, repeated work, inconsistent assumptions, and failure recovery against one well-designed agent.

## Make the handoff explicit

Pass the task, permitted scope, source references, unresolved questions, and expected result. One agent’s conclusion is still a claim for another agent to inspect, not an authorization. Assign ownership of the final outcome and of any shared state.

## Evaluate the complete result

Measure task success, review effort, latency, and full cost. Test a missing specialist response, conflicting evidence, and a repeated request. See [the technology decision](/decisions#cd-21-multi-agent-orchestration-vs-a-single-good-loop) and [systemic audit investigation](/use-cases/systemic-audit-issues).
