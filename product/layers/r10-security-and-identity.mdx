A model cannot reliably tell an instruction from data. So an attacker will sometimes trick an agent, and the design must assume it. The security and identity layer (R10) decides who each agent is and what it may do. It is one of the [fourteen layers](/layers) you own. Today it holds workforce identity, privileged access, customer identity and security monitoring. For agents, this layer must make sure a tricked agent can do very little harm. Each agent gets its own short-lived identity, with only the access its task needs. A policy decision point checks every action that matters, and the agent cannot skip it. That check sits outside the model, as [enforcement outside the model](/architecture/enforcement) describes. AI-based filters may warn, but they never decide. In the four [deterministic zones](/architecture/deterministic-zones), models may take permission away, never grant it. This layer provides identity and policy, one of the [seven capabilities](/architecture/system-view) an agent platform adds.

## What agents add

<GuideFigure id="layer-10-hero" fullWidth />

### A model cannot tell instructions from data

A transformer model treats every <Term k="token">token</Term> the same way. A token is the small unit of text a model reads. So training alone cannot make it separate commands from data (Bhattarai and Vu, February 2026). EchoLeak shows what follows (CVE-2025-32711, severity 9.3 out of 10). It was a zero-click leak of data through a mailbox attached to Copilot. The injected instructions looked like ordinary content to the model. Unit 42 has since documented indirect prompt injection in the wild. A <Term k="prompt injection">prompt injection</Term> is an instruction hidden in content the agent reads. So assume injection sometimes succeeds. Identity scoping, the policy decision point and payment mandates all exist to cap what a tricked agent can do.

### Each agent has its own identity

Register every agent with a named owner and a [risk tier](/architecture/risk-profile). The tiers are Tier 1 (basic), Tier 2 (enhanced) and Tier 3 (strict). Remove shared credentials first. An agent using a person's login is shared credentials (ID1), the pattern to remove. Every agent needs at least its own identity (ID2), as the [delegation chain](/architecture/delegation-chain) sets out. The delegation chain traces every action to the person who asked.

Keep standing access small. Grant extra access just in time for one task, and let it drop back on its own [vendor]. To authorise a single action, use OAuth Rich Authorization Requests (RFC 9396). These put the action's details inside the access token, instead of a broad scope. Credentials are short-lived and cryptographically anchored, in the words of the US agency CISA. NIST's National Cybersecurity Center of Excellence has a demonstration project dated February 2026. It joins OAuth, SPIFFE and MCP into this chain. SPIFFE is a standard that gives running software its own proof of identity.

The <Term k="kill switch">kill switch</Term> is an identity feature. Time to revoke an agent's credentials is the number that proves it works, so drill it.

A few long-lived agents may also need an agent user account. That brings a mailbox, a meeting seat or directory visibility. Grant one only where the sponsor accepts that the agent becomes findable and can be phished. The [productivity and collaboration layer (R08)](/layers/r08-productivity-and-collaboration) covers that grant.

Agent identity products are still arriving. As of 14 October 2026, only Microsoft confirms on its own pages that its agent identity is generally available [vendor]. That is Entra Agent ID, with Agent 365 and its agent registry. Other vendors' release claims come from trade press, their own blogs or announcements without a date.

### A policy decision point the agent cannot skip

<TeachingIllustration src="/images/layers/r10-policy-decision-labeled-v1.webp" title="Every action that matters meets a decision the agent cannot bypass" alt="An agent identity with a short-lived credential sends an action request. A fixed policy decision point checks it, using the caller, the action, the resource and the context. If allowed, the tool runs and an audit receipt is written. If blocked, the request goes to a person. A warning says that when the policy service is down, the action stops. The line underneath reads: the agent cannot bypass the decision." caption="The decision uses fixed inputs. It fails closed: if the decision service is down, the action stops." />

The authorisation check is policy written as code, in the path of every <Term k="tool">tool</Term> call. A <Term k="policy decision point">policy decision point</Term> evaluates it, and the agent cannot bypass it. The tool gateway in the [integration fabric layer (R03)](/layers/r03-integration-fabric) enforces the answer. This layer decides, and the gateway enforces.

The engine choice is a trade. Cedar evaluates in under a millisecond and is formally verified, but holds no state. Open Policy Agent, with its Rego language, handles richer lookups against outside data. OpenFGA and SpiceDB cover permissions based on relationships. The decision point fails closed. If the engine is down, actions that matter stop.

Two extra checks exist, at different stages of maturity. Microsoft's FIDES information-flow control is experimental and Python-only (7 October 2026) [vendor]. It is not supported where code runs. In Microsoft's own test it held policy-breaking injections to zero, against 20 to 152 without it [vendor]. Where code runs, only the sandbox, network egress and credential controls protect you. AWS's Bedrock Automated Reasoning checks verify outputs against formal logic [vendor]. They have been generally available since 6 August 2025.

### Filters warn, they never decide

Published tests settle this. In one 2025 study, 72 to 77 percent of attacks got past three commercial filters. In some setups the figure reached 100 percent. Attacks tuned to the defence do even better. An October 2025 study broke 12 published defences, most at above 90 percent success (arXiv 2510.09023). Human red-teamers beat every one. NIST saw agent-hijacking success rise from 11 to 81 percent once attacks were tuned to the defence (January 2025).

Vendors report far lower rates, on their own tests that do not adapt [vendor]. The one setup measured at zero bypass blocked 16.22 percent of legitimate requests. It also added about 1.5 seconds per call. A policy engine decides in under a millisecond to a few milliseconds, about a thousand times faster. Filters are also a target, because an attacker can trip one on purpose to block service. So keep <Term k="guardrail">guardrails</Term> for content policy, personal data detection and telemetry, where a miss is tolerable. They never authorise an action.

### In four zones, a model may block but never approve

<TeachingIllustration src="/figures/architecture/deterministic-zones-walls.svg" mobileSrc="/figures/architecture/deterministic-zones-walls-mobile.svg" expandable title="Models may take permission away, never grant it" alt="Four zones sit around a model's reasoning. In access and entitlements, a policy decision point decides over verified identity and fails closed. In movement of money, the rail or issuer decides by checking a signed, scoped credential. In safety actuation, operators, interlocks and the safety instrumented system decide. In formal regulatory records, a named person attests and the system of record keeps it unchanged. In every zone the model may analyse, draft, recommend, flag and block. It may deny, escalate or quarantine, but never grant. Beside the zones sit the destruction rule and the rule for decisions about people. A strip of six yes or no questions finds the zones in an enterprise." caption="Inside the zones a fixed rule or a named person decides. The model may advise or block." />

The four zones are access, money movement, safety actuation and formal regulatory records. In them, a fixed rule or a named person decides. Model outputs are advice. Models may take permission away, never grant it. Machine learning signals inside three zones are part of the design. Entra ID Protection feeds risk scores into fixed Conditional Access rules. Mastercard scores every transaction while authorisation stays rule-based. Filings are drafted with AI, then a person attests to the record.

Safety actuation is the one zone where standards keep machine learning out of the function itself. IEC 61511 governs safety instrumented systems, the certified equipment that shuts a process down safely. ISO/IEC TR 5469:2024 places AI outside the fixed safety function. Records rules ask for accountability and records that cannot be changed. They do not ask for fixed generation. FINRA notice 24-09 (June 2024) confirmed that existing obligations apply whatever the technology. ESMA said the same in May 2024.

Deloitte Australia repaid the final instalment, A$97,587, of a contract worth about A$440,000. That followed fabricated references found in a government report (October 2025).

Two rules sit beside the zones. The [destruction rule](/architecture/deterministic-zones#the-destruction-rule) covers deleting or resetting production systems. [The rule for decisions about people](/architecture/deterministic-zones#the-rule-for-decisions-about-people) says a named person decides any significant decision about a person.

### A worked example: a plant investigation agent

Take a generator whose agent investigates a pump that keeps tripping. The agent runs on the business network or in the cloud, not in the plant. It needs its own identity in IT and in the plant network's buffer zone. It reads historian copies, the maintenance system and the lab system through a read broker. It may write only a draft notification in the maintenance system. Nothing it does writes to a control system, a safety system or a protection relay. Nothing it does issues a permit or applies an isolation. Those stay with operators and certified systems, inside the safety actuation zone.

### Payment mandates follow the same pattern

The card networks built the same pattern on their own. Visa's Trusted Agent Protocol (October 2025) uses tokens limited by amount, merchant and category. Mastercard Agent Pay (April 2025) uses tokens bound to agent, merchant and consent, revocable in real time. Google's Agent Payments Protocol (September 2025) uses signed <Term k="mandate">mandates</Term> with hard limits. A mandate is a signed permission to spend: how much, with whom, for what, and until when. The mandate does not protect how the agent forms its intent. Testers in January 2026 used prompt injection that stayed inside a mandate's limits. The mandate limits the damage. Defending against injection, and a person confirming intent, are still needed.

### The security team needs agent detections

Four public documents now describe how agents get attacked. The OWASP Top 10 for Agentic Applications (9 December 2025) runs from goal hijack to rogue agents. Two of its entries change enterprise controls: memory poisoning, and attacks on people's trust in agent messages. MITRE ATLAS added fourteen agent techniques in October 2025. Microsoft's failure-mode taxonomy (June 2026) counts 99 vulnerabilities in 2025 linked to MCP. Six national cyber agencies advise starting low-risk and granting no broad access (April to May 2026). Map detections to MITRE ATLAS and OWASP. Write agent runbooks. Keep reasoning traces and mandate logs as evidence. Spotting abnormal agent behaviour is still unsolved in mainstream security monitoring tools.

## What must be true before an agent touches it

Before an agent holds any credential, these must hold.

- **It is registered.** It has a registry record, a named owner, a sponsor and a risk tier, as the [agent lifecycle](/architecture/agent-lifecycle) sets out.
- **It shares no one's login.** It has its own identity (ID2), and the delegation chain holds at every hop.
- **Its access is small and short-lived.** Extra access is granted per task and expires on its own.
- **A decision point guards every action that matters.** It fails closed, and the agent cannot bypass it.
- **Filters stay off the authorisation path.** They may warn or block content, but never approve an action.
- **The zones are mapped.** Every action in access, money, safety or formal records has a fixed rule or a named person deciding.
- **It can be switched off fast.** Kill switches exist in identity, the runtime and the gateway. Time to revoke is drilled.
- **The security team can see it.** Detections, runbooks and agent evidence reach the security operations centre.

The enforcement point is the policy decision point, enforced at the tool gateway. Both sit outside the model.

Regulators already expect this. Australia's Information Security Manual added agent controls in its September 2026 release (ISM-2133 to ISM-2135). The control numbers come from a compliance firm's walkthrough, so check them at cyber.gov.au. APRA wrote to banks and insurers on 30 April 2026. It expects an AI inventory, ownership across the lifecycle and security testing of AI-written code. It also expects privileged-access management for non-human actors, under CPS 230 and CPS 234. The Monetary Authority of Singapore issued final AI risk guidelines on 7 October 2026. They ask for an AI inventory that can carry agent identifiers and tool access. They set no agent-specific controls yet. The [governance, risk and sovereignty layer (R11)](/layers/r11-governance-risk-sovereignty) covers the wider governance rules.

## Choices and their verdicts

Each choice is the common choice, tested against the simplest credible alternative. The full records are in the [decision catalog](/decisions).

- **[Guardrail products or fixed gates](/decisions#cd-16) (CD-16):** fixed gates own the authorisation boundary. Filters are advice wherever they run.
- **[Dedicated AI security platforms or SIEM extension](/decisions#cd-13) (CD-13):** the market is folding AI security into existing platforms. Buy that way, but spotting abnormal agent behaviour is still unsolved.

## Concerns this layer must honour

The ten cross-cutting concerns are set out in the [concern matrix](/architecture/concern-matrix). This layer carries a specific duty for seven of them.

- **Identity and access:** the core of this layer. Registered agent identities, just-in-time access, short-lived credentials and a decision point on every action that matters.
- **Observability:** agent security telemetry flows to the SIEM. Baselining normal agent behaviour is an open gap.
- **Traceability and audit:** policy decisions, mandate logs and reasoning traces are kept where they cannot be changed.
- **Impersonation:** agent identity is proven, and agent messages to people resist spoofing.
- **Sovereignty:** credentials, tokens and telemetry stay in the required place.
- **Safety and oversight:** the four zones, intent confirmation for actions that matter, and the kill switch.
- **Resilience:** revocation drills, and fail closed when a policy engine fails.

## Evidence and limits

The incident record supports the core reason. It includes EchoLeak, 99 MCP-linked vulnerabilities in 2025, and injection seen in the wild. Published attack studies support the verdict on filters, including tests with attacks tuned to the defence.

Several figures come from vendors and carry the [vendor] tag. They include the identity release dates, the FIDES result and the reasoning checks. Vendor results for model-based reviewers are not replicated. They were probably measured without adaptive attacks.

Some points are second-hand. They include the six-nation guidance date, the ISM control numbers and most agent identity release claims. The standards for passing delegation between agents are drafts. The FINRA 25-07 reading traces through a vendor blog, so check it at finra.org before relying on it.
